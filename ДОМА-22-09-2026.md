## Быстрый старт дома

1. `git pull origin main` в `D:\Project\CoreX` (или клон свежий).
2. Python **3.11 или 3.12** нужен для Aider (на 3.14 пакет не ставится).
3. При старте загрузочный экран сам проверит Python 3.11 и Aider и предложит скачать, если их нет.

6. В чате **Оркестрация**: движок **Aider** (по умолчанию) или **CoreX**.

Ключи онлайна не в git: `%LOCALAPPDATA%\CoreX\secrets\`.

## Что сделали сегодня (22.09.2026, работа)

### 1. Aider как движок кода

- Режим **Aider / CoreX** в UI (по умолчанию Aider).
- Скилы, персоны, язык, локальные (Ollama) и онлайн-модели уходят в промпт Aider.
- Без автокоммита (`--no-auto-commits`).
- Sidecar: `.venv-aider` + `backend/requirements-aider.txt` + `scripts/ensure_aider_venv.bat`.
- Файлы: `backend/core/aider_service.py`, `backend/core/coding_engine.py`, правки `orchestrator.py`, `ws_server.py`, UI `CodingEngineSelector`.

### 2. Баги запуска Aider (уже в коде)

| Симптом | Причина | Фикс |
|---------|---------|------|
| Пустая «Ошибка выполнения задачи» + крутится «Модель» | `--chat-mode code` в Aider 0.86 нет | Не передаём `code`; вопросы → `ask` |
| `NotImplementedError (без текста)` | Windows `SelectorEventLoop` + `asyncio.create_subprocess_exec` | Aider через `subprocess.Popen` в потоке |
| Aider лез в git CoreX | Пустой проект без `.git` | `git init` в проекте + `--subtree-only` |
| Длинный RU-промпт | argv Windows | `--message-file` в `chat/_aider_message.txt` |
| Трасса «думает» после конца | `aider_start` оставался `active` | `aider_done` / `aider_failed` + UI гасит active после `task_end` |
