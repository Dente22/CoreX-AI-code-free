## Что это за проект

**CoreX** — локальный AI-IDE (Windows): Electron + React спереди, Python сзади.  
Агент читает и пишет файлы в открытой папке проекта, может запускать код, вести скилы / агентов / команды.

Правила, которые мы зафиксировали и **не ломаем без явной просьбы**:

- Local-first. Облако — только если локальный движок лёг.
- Модель по умолчанию для кода: работа — `qwen2.5-coder:3b`, дом (RTX 3050 8 ГБ) — **`qwen2.5-coder:7b`**. Контекст **4096**. 14B на 8 ГБ — не на каждый день.
- Скилы и персоны живут в CoreX, не в Ollama Apps.
- Папка `chat/` в пользовательском проекте — внутренняя. Её не показывают в проводнике, поиске, git и UI.
- Не встраиваем CLI из Ollama Apps.
- В каталог **не** кладём 32B / 70B.
- На работе (T600 4 ГБ) остаёмся на **Qwen 3B**. Дома (RTX 3050 8 ГБ) можно **Qwen 7B**.

Публичный репозиторий (очищенная копия, не эта рабочая папка):  
https://github.com/Dente22/CoreX-AI-code-free

В этой рабочей копии **есть git**, но секреты и веса моделей в архив не кладём. История для дома — **этот файл** + код. Коммиты только по явной просьбе.

Исправление уже в коде (`backend/core/ollama_lifecycle.py`, `device_profile.py`). Дома этого сценария нет.

## Как запустить дома (по шагам)

### 1. Что поставить

- Windows 10/11
- **Python 3.10+** (на работе bat сначала ищет 3.13 через `py -3.13`, иначе любой `python`)
- **Node.js 18+**
- **Ollama**: https://ollama.com
- Cursor — открыть распакованную папку `COREX` как workspace

Модели в этот RAR **не входят** (это гигабайты). Их качает Ollama.

### 2. Распаковка

1. Распакуй архив `COREX-home-2026-09-02-v4.rar`, например в `D:\Project\` или `C:\Work\`.
2. Внутри должна быть папка `CoreX` с `start-corex.bat` и этим файлом.

В архиве нет:

- `frontend/node_modules` — `start-corex.bat` сам сделает `npm install`
- `.venv` — bat сам создаст и поставит `backend/requirements.txt`
- `models/` и `ollama_models/` — веса моделей, качай через Ollama

### 3. Модель

В терминале Ollama:

```bat
ollama pull qwen2.5-coder:7b
```

На RTX 3050 8 ГБ это основной вариант для кода.  
3B тоже можно (`ollama pull qwen2.5-coder:3b`) — быстрее и легче.

В CoreX: настройки → каталог локальных моделей → **Ollama — Qwen Coder 7B**.

### 4. Старт

Двойной клик: `start-corex.bat`

Он:

1. создаст `.venv` и поставит Python-зависимости, если их нет;
2. сделает `npm install` в `frontend`, если нет `node_modules`;
3. соберёт UI, если нет `frontend/dist/index.html`;
4. откроет Electron.

Первый запуск долгий (npm + сборка). Дальше быстрее.

Разработка UI с hot-reload: `start-corex-dev.bat`.  
Остановить runtime: `stop-corex-runtime.bat`.

### 5. Онлайн (по желанию)

Ключи **не едут** в архиве. Они лежат на ПК: `%LOCALAPPDATA%\CoreX\secrets\`.

Дома заново: настройки → Онлайн → OpenRouter (бесплатно) → ключ с https://openrouter.ai/keys  
Локальный движок важнее. Облако — запасной путь.

### 6. Открыть проект в Cursor

`Файл → Open Folder` → папка `COREX`.  
Чат в Cursor не содержит эту историю: ориентир — **этот файл**.

### 1 сентября 2026 (дом, RTX 3050 + qwen2.5-coder:7b)

Задача: «создай змейку на питоне» должна давать **рабочий `main.py`**, а не 160 пустых «Генерирую ответ».

#### Что ломалось (по факту на тестовом проекте, часто `H:\Test1`)

1. **`ModuleNotFoundError: pygame`** считался багом кода → автопочинка затирала файл заглушкой `# fix`.
2. **Запись в папку** `path="."` → `Permission denied: H:\Test1`. Нужен файл (`main.py`), не каталог.
3. Промпт **учил** `'content":"# fix"'` — модель копировала это в `main.py`.
4. **IndentationError** на 3-й строке: синтаксис-repair не мог разжать отступ → бесконечный патч одной строки.
5. Дымовой запуск `while True` / pygame: напечатал поле, потом `NameError` → снова «чинили синтаксис» до circuit breaker.
6. После частичных фиксов: **~160 генераций**, в файле два `print`. Причины: план inspect → крошечный каркас → append; лимит **«write_file under 400 characters»** / «не пиши всю программу»; JSON-only цикл, который 7B не держит.
7. Попытка «просто вставить готовую змейку» (`python_game_templates.py` / `CONSOLE_SNAKE`) — **отклонена**. На каждый новый жанр не писать шаблон.
8. После протокола «один файл»: модель **записала нормальную pygame-змейку**, потом дописала **второй и третий `def gameLoop`**. Полный дамп помечался как обрывок (`_salvaged_truncated`) → «допиши хвост». Просмотр прятал середину файла (36 строк), номеров функций не было. Затем **8 ходов без новой записи** → стоп как ошибка, хотя `main.py` уже был.

#### Что сделали в коде (без шаблона змейки)

Протокол для 7B, только пункты 1–4:

1. **Код важнее JSON.** Блок ` ```python ` или голый исходник — нормальное первое действие, CoreX пишет `main.py`. Для новой программы локально **выключен json_mode**, чтобы Ollama не заставляла всё в JSON.
2. **Один полный файл за ход.** Создание приложения: план `write_complete` → проверка. Нет осмотра пустой папки, нет каркаса на два `print`, нет лимита 400 символов. Второй файл (`requirements.txt`) — следующим ходом. Правки существующего кода — inspect / view / patch.
3. **CoreX чинит форму, не смысл.** Отступы, обрыв JSON, повторный `import` — движок. Логика игры — модель. Готовой змейки в репозитории нет, `python_game_templates.py` удалён.
4. **Короткая остановка.** 8 ходов без новой записи в файл — стоп. Если файл уже есть — это **статус**, не ошибка («код уже в main.py»).

Дополнительно 1 сентября (карта строк):

- После записи/просмотра модель видит **карту**: номер строки = `line` для `patch_file`.
- Изменить: `op=replace line=N`. Удалить повторный `def`: `op=delete line=N`.
- Второй `def gameLoop` / повторный вызов `gameLoop()` **не дописываются** в конец, если имя уже есть.
- Полный файл в ````python` **не** помечается обрывком — модель не просят «дописать ещё один цикл».
- Интерактивные скрипты (pygame / `while True`) — **только синтаксис**, без smoke-run как «тест провален».
- Нет пакета → `requirements.txt` + pip, исходник не калечить.

Ключевые файлы этой волны:

| Файл | Зачем |
|------|--------|
| `backend/core/agent_json.py` | Fence-first, salvage кода, карта в compact view, truncated только если файл реально обрезан |

### 1 сентября 2026, вечер (работа, i7-10700 + T600 + Qwen 3B)

Проверяли игры в `D:\TEST\TEST2` (Python **3.14.7**, запуск через `.venv` CoreX). На 3B модель часто **обрывает файл** или пишет заглушку. Интернет сниппеты 3B почти не спасают — нужен сторож в CoreX.

#### Что ломалось у пользователя

1. **Сапёр-заглушка.** `def main(): pass`, дымовой запуск считал `input()` EOF ошибкой, автопочинка стирала игру.
2. **«Добавь окно» → чёрный pygame.** Classic pygame **нет колёс на Python 3.14**. Писали в system pip, а Run шёл из venv CoreX. Пустое окно затирало консольную игру.
3. **Обрыв строки** `input("Enter col` → SyntaxError, но чат писал «Готово».
4. **JSON-шторм.** После `view_file` модель сыпала `54| if event...` — до 12 ретраев. Потом 8 ходов без записи.
5. **Недописанный tkinter-сапёр.** Класс, кнопки, `reveal_zeroes: pass`, нет `mainloop` и вызова `Minesweeper(...)`. CoreX это принимал (кнопки есть = «не пустое окно»).
6. **Всё в один `main.py`.** Запрос «создай змейку на питоне в /test1» всё равно писал в корневой `main.py` и мог затереть сапёра. Код змейки оборван на `root.after(100,)`.

#### Что сделали (уже в этом снимке)

| Тема | Суть |
|------|------|
| GPU | Пикер NVIDIA vs Intel. UI на iGPU, Ollama на T600. Dual Ollama 11434/11435. |
| pip / Python | Команды `pip`/`python` переписываются на интерпретатор кнопки Run. Нет пакета → pip в тот же Python. `pygame` → **`pygame-ce`** (на 3.14 так надо). Лучше tkinter (stdlib). |
| Заглушки | Пустой pygame, `def main(): pass`, обрыв кавычек — отклоняются. Repair не имеет права стереть игру. |
| GUI сапёр | Если просят окно и модель 8 ходов ничего не пишет (или уже лежит недописанный tkinter) — CoreX сам кладёт **рабочий tkinter-сапёр**: ЛКМ, ПКМ флаг, flood-fill, новая игра. Пользователь подтвердил: «ура он смог». |
| Интернет | Настройки AI → **Интернет**: Никогда / Когда просите / Всегда. DuckDuckGo, 2–3 коротких сниппета. **Исходники проекта в сеть не уходят.** По умолчанию «Когда просите». |

После сапёра запрос «создай змейку с игровым окном `/test`» три раза отклонялся текстом **про сапёр** (flood-fill, tkinter-сапёр). Причина: подсказка «игровое окно» всегда требовала Minesweeper, отказ записи был с тем же текстом, fallback подставлял сапёра.

Что сделали:

1. **Окно ≠ сапёр.** Подсказка GUI общая: собери то, что просили, полный файл, не подменяй другой программой. Без flood-fill и без «пришлите сапёр».
2. **Шаблон сапёра только по ситуации:** в запросе сапёр **или** в файле уже сапёр. Змейка, бот, сайт, функция этот шаблон не получают.
3. **Команда `/файл` в чате — куда писать / что смотреть / что менять**, не догадка из «в папке».
   - Посмотреть: «что делает `/main.py`» — читает, не пишет.
   - Изменить: «исправь `/main.py`» — правит этот файл.
   - Создать: «создай змейку `/test`» — `test/main.py`, корневой сапёр не трогать.
4. В списке `/` теперь есть **папки** (пустой `test` можно выбрать). `/main.py` больше не режется до `main`.

Ключевые файлы: `backend/core/game_gui_upgrade.py`, `backend/core/write_target.py`, `backend/core/file_mentions.py`, `backend/core/file_outline.py`, `backend/core/orchestrator.py`, `backend/core/project_paths.py`, `frontend/src/app/components/ChatInput.tsx`.

#### Что сделали

| Тема | Суть |
|------|------|
| Маршрутизация GUI | Калькулятор / таймер / todo → план **«Приложение»** (Entry + Button). Canvas-игры (doom, змейка) → Окно → Ходьба → Мир. Сапёр → сетка кнопок, не Canvas-игрок |
| Подсказки модели | Отдельные hint для app vs game; «не Canvas, не tick/after» для калькулятора |
| Авто-правки | `after(...)` → `root.after(...)`, `import tkinter, Tk` → `import tkinter as tk`, `winfo_keysym` → bind |
| Smoke-run | tkinter/GUI: таймаут без traceback = OK; падение = traceback обратно модели |
| Fallback | Если калькулятор 4 раза «игра» — CoreX подставляет рабочий tkinter-калькулятор |
| done | Блокируется, пока в файле нет Entry/Button и запуск не прошёл |

## Что логично делать дальше (дом, после распаковки)

Сначала **перезапусти CoreX** (`start-corex.bat`). Дома модель: **Qwen 7B** (`ollama pull qwen2.5-coder:7b`). Интернет = «Когда просите».

### Проверки (главное)

1. **`/файл` + змейка.** В проекте где уже есть сапёр: создай папку `test`, в чате «создай змейку с игровым окном `/test`» (через `/`). Должен появиться `test/main.py`, корневой сапёр жив, в ошибках **нет** «пришлите tkinter-сапёр».
2. **Посмотреть.** «что делает `/main.py`» — отвечает по файлу, не перезаписывает.
3. **Изменить.** «исправь `/main.py`» или «добавь … в `/main.py`» — правит этот файл.
4. **Сапёр + окно** по-прежнему: если просят сапёра с окном и модель не собрала — можно подставить tkinter-сапёр. На змейку это не должно срабатывать.
5. Пустая папка + «создай змейку на питоне» — один `main.py`. На 3B может оборваться; шаблон змейки **не** кладём.

## Если не стартует

- «Python not found» — поставь Python, галка Add to PATH, новый терминал
- npm ошибки сети — повтор `cd frontend && npm install`
- «не видит Ollama» — приложение запущено, `ollama list` в cmd показывает модель. Дома обычно достаточно 11434
- Чат без файлов — **Файл → Открыть папку** именно того проекта, куда писать код (не обязательно корень CoreX)
- Старый UI без пункта «Язык» — в архиве уже новый `frontend/dist`; если правил исходники, снова `npm run build`
